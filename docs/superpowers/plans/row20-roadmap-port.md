# Row 20 — Roadmap skill ported: import + overlay, 4-turn phases, gate manifest, ping as a post, scratch run, dogfood

**Goal.** The harness roadmap skill runs as a hub run: the canonical `~/.claude/skills/roadmap/` folder is imported unchanged, one hub-side overlay maps its phases onto ≤ 4-turn exchanges and names the gates, the ping is the run-ending post, and it is proven by a scratch-repo run with a Codex plumbing worker, then by a ChopItUp dogfood run driven from the owner's phone.

**Architecture.** `SkillImport` gains `--overlay <dir>`: harness skill + `OVERLAY.md` + `scripts/*.ps1` are copied and hash-pinned as one manifest, so the overlay renders inside the skill fence with SKILL.md's integrity claim (row 11's D-j objection answered: pinned, not unpinned). The overlay's frontmatter carries `run: true` and the gate list; the gate scripts wrap the harness preflight scripts by relative path, run the repo tests, and do the branch work the spawn deny list forbids. `--set-classes` gives Codex rows a class. Spawn configuration gains a gate ceiling below the spawn clock, the per-server MCP `timeout` and the idle env var, all probed. A live check drives a lite-path run on a scratch .NET repo. The dogfood run is the row's final task and the only owner-physical step.

**Author model:** Fable 5.1 (`claude-fable-5-1`). Session routing matches the tier (HIGH → Fable); critique pass 1 = `opus`, pass 2 = `fable`.

**Blast radius: HIGH.** Cross-process contracts on three sides: the skill import format and hash manifest (what `run_gate` will execute), spawn command lines and environment for both CLIs, and a deploy to the live hub with host-command writes into its data directory. Under-tiering would skip the synthetic dry run and the self-check that the dogfood depends on.

*Written for builder-subagent execution; if something doesn't match, STOP and report rather than guess.*
